## 一、要解决什么问题

端到端自动驾驶轨迹规划有两个主流范式，各有致命短板：

| 范式 | 优点 | 致命伤 |
|---|---|---|
| **自回归模型 (AR)** | 因果分解，时序依赖建模好 | 逐步解码 → 误差累积，缺乏全局优化视野 |
| **扩散模型 (Diffusion)** | 全局去噪生成，多模态强 | 缺乏因果约束，安全交互场景不可靠 |

**核心问题：** 因果建模和全局优化被人为割裂了，没有一个框架能把两者统一到同一个轨迹分布里。

---

## 二、整体框架：Chain → Flow

### 核心公式（概率混合分布）

将轨迹规划建模为一个混合分布：

```
P(Y|O) ≈ Σ P(Y|Y_AR^(k), h_VLM) · P(Y_AR^(k)|O)
         ↑ Flow 模块            ↑ Chain 模块
```

- **Chain**: 生成 K 个因果一致的粗候选轨迹
- **Flow**: 用 VLM 语义特征引导扩散模型，在每个候选周围做残差修正

---

## 三、Chain 阶段：自回归轨迹生成

### 怎么做

1. 初始化 **K 个可学习的 Trajectory Queries**（如 K=6），每个 query 代表一个潜在的轨迹模式
2. 每个 query 与 **BEV 特征** 做 cross-attention，从场景中读取环境信息
3. **自回归逐帧预测控制量**（加速度 a_t、角速度 ω_t），而非直接回归坐标

### 自行车模型（Bicycle Model）

```
预测 (a_t, ω_t) → Bicycle(y_{t-1}, a_t, ω_t) → y_t
```

- 保证每条候选轨迹**物理可执行**，不会出现瞬移/急转
- 降低学习难度——模型只需学控制量（有界、低维），而非全局坐标

### 训练：WTA（Winner-Take-All）

- K 条候选并行生成
- 只选离真值最近的那条算 loss 反传，其余 K-1 条 loss=0
- **无显式的 diversity loss**，靠随机初始化差异 + WTA 竞争让 queries 自发分化
- 每条 query 最终学会一种驾驶模式（直行、左转、让行等）

### 约束问题

- 没有显式约束（如 L2 正则惩罚 query 相似度）
- 也没有运动学先验初始化（如预定义左转/直行模式）
- 纯靠 WTA 竞争 + 大数据驱动，属于"轻量型"做法
- 风险长尾场景可能所有 query 都去拟合常见模态

## 四、Flow 阶段：VLM 引导的残差扩散

### 核心思路

不生成完整轨迹，而是学习 **残差**——AR 候选和真值之间的偏差：

```
ΔY_k^* = Y^* - Y_AR^(k)
最终轨迹 = Y_AR^(k) + ΔŶ_k
```

### 残差扩散

```
z_t = √ᾱ_t · ΔY_k^* + √(1-ᾱ_t) · ε
ε̂ = DiT(z_t, t, c_ego, h_VLM, Y_AR^(k))
```

- 在 **残差空间** 做扩散，而非全局轨迹空间
- 得：扩散模型只学"AR 没做对的部分"，训练更高效

### 噪声调度

- 沿用 **DiT 标准 cosine noise schedule**（Improved DDPM）
- 训练时完整 1000 步扩散链
- 推理时用 **DDIM，默认只用 4 步**（12 步 saturate 追平人类水平）
- 训练时 ᾱ_t 遵循 cosine 衰减，具体数值表未列出（论文引用 DiT 标准实现）

### VLM 注入方式

```
前视单图 → VLM (InternVL 2B, ReCogDrive SFT, 冻住)
         → 提取最后一层隐藏层特征 h_VLM
         → 注入 DiT (cross-attention) 做残差修正的条件
```

## 五、VLM 详解

### 输入：前视单张图像（不是环视）

- VLM 基于 **InternVL 2B**，原生单图模型
- 看不到两侧和后方场景
- SFT 微调用的也是单张前视图 + QA 对

### 为什么合理？

VLM 的任务不是"完整感知"，而是**场景语义理解**。前方视野已覆盖驾驶决策中绝大多数需要语义推理的场景（红绿灯、行人穿行、前车意图、路口拓扑）。两侧和后方由 Chain 模块的环视 BEV 特征补全。

### SFT 微调阶段（一次性预训练）

用两类 QA 数据教 VLM 看懂驾驶场景：

**① 场景理解（Environment Understanding）**
- "自车前方是否有红灯？"
- "右侧车道是否有行人？"
- "导航路线要求直行还是左转？"

**② 轨迹问答（Trajectory QA）**
- "这条轨迹是否与障碍物碰撞？"
- "轨迹是否保持在当前车道内？"
- "自车下一步应该加速、减速还是保持？"

### 推理时（重要澄清）

**没有文字提示词。** VLM 只接收图像，不接收任何 QA 问题。SFT 的作用是让 VLM 的隐藏层特征空间针对驾驶场景做了优化。推理时直接提 h_VLM 用于扩散条件化。

```
误解：图像 + "前方有红绿灯吗？" → VLM → 答案
实际：图像 → VLM → 隐藏层 h_VLM → DiT
```

### VLM 全程冻住

- 不参与 ChainFlow-VLA 的端到端训练
- 不因扩散目标做任何优化
- 只作为"场景语义编码器"提供先验知识

## 六、传感器配置总结

```
环视 8 相机 → DrivoR backbone → BEV 特征 → Chain（AR 粗提案）
                                             ↓
前视单图    → VLM (InternVL 2B) → h_VLM → Flow（残差修正）
                                             ↓
                                          Scorer → 选最优轨迹
```

| 模块 | 视野 | 原因 |
|---|---|---|
| **Chain (AR)** | 360° 环视 | 规划需要完整感知周围车辆、车道拓扑 |
| **VLM** | 前视单图 | 只需理解前方场景语义，提供修正信号 |

## 七、训练流程

### 两阶段训练

**Stage 1（25 epochs）：**
- 用 LoRA 微调 image encoder
- 训练 Chain 模块 + Scorer
- Loss: L_traj + λ₁ · L_scorer
- WTA 选最优候选

**Stage 2（40 epochs）：**
- 冻结 Chain
- 训练 Flow 扩散模块 + Scorer
- Loss: λ₂ · L_diff + λ₃ · L_traj + λ₄ · L_scorer

**训练资源：** 8 张 NVIDIA A800 GPU，per-GPU batch size=8

**优化器：** AdamW，lr=2e-4（按 B/64 缩放），linear warmup 10% + cosine decay

**Loss 权重：** λ₁=1, λ₂=10, λ₃=20, λ₄=4

## 九、评分

| 维度 | 评分 | 说明 |
|---|---|---|
| **结果指标** | **9/10** | NAVSIM v1 榜首 94.85，追平人类水平，领先第二名有明显差距。但仅验证了一个 benchmark，泛化性待验证。 |
| **推理速度** | **7/10** | DDIM 4 步去噪 + AR 一步生成，推理效率不错。但两阶段流水线（AR → VLM → DiT → Scorer）仍有串行开销。 |
| **可落地程度** | **6/10** | 需要 VLM (2B) + AR + DiT + Scorer 四个组件串行推理，显存/算力要求高。训练需 8×A800。更适合作业化远程部署，不适合车端实时推理。 |
| **创新价值** | **8/10** | Chain + Flow 的职责分离设计很干净，"VLM 当语义修正器而非生成器"的洞察击中要害。残差空间扩散降低了学习难度。但各组件（AR、DiT、VLM）本身非原创，组合创新为主。 |
| **综合** | **7.5/10** | 设计优雅、效果惊艳的工程创新，解决了一个真实痛点。不是颠覆性理论突破，但在落地思路上有很多值得借鉴的设计选择。 |

## 十、关键设计启示

1. **职责分离**：AR 管因果和物理可行性，VLM 管语义修正，扩散管全局优化 —— 各司其职
2. **残差空间**：让扩散模型只在"偏差"上学习，而非整个轨迹分布，训练效率更高
3. **VLM 即编码器**：不用做生成器，只提供 hidden states，信息无损且不需要额外适配
4. **Single-to-multi**：VLM 看前路单图，BEV 看全局，两条信息流汇合
